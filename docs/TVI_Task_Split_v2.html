2. CHI TIẾT 4 PHẦN VIỆC

PHẦN 1 – TOPOLOGY, LAYER 2, HSRP, DHCP/DNS (Bước 1, 3, 4)

Mục tiêu: dựng khung lab cho cả nhóm vào ngày 1, sau đó hoàn thiện L2 + dự phòng gateway + dịch vụ IP.

  1. Dựng lab EVE đúng mục 1.1–1.2 (tên node, cổng). Export file TVI_Lab.unl gửi nhóm ngay tối ngày 1. Cài Cloud1/pnet1 cho mạng quản trị (hướng dẫn mục 3.2).
  2. Sơ đồ Draw.io TVI_Logical_Topology.drawio/.png: icon Cisco chuẩn, ghi interface, VLAN, subnet, AS BGP, tunnel, ranh giới LAN / WAN / ISP (demarcation) và vùng L2/L3. Thêm 1 sơ đồ vật lý đơn giản (cabling) → điểm tối đa rubric báo cáo mục 2.
  3. VLAN & trunk: tạo VLAN theo 1.3 trên mọi switch; trunk 802.1Q giữa switch và lên router (switchport trunk encapsulation dot1q, switchport mode trunk, switchport nonegotiate). Cổng thừa: switchport access vlan 999 + shutdown.
  4. EtherChannel LACP: Po1 CORE↔DIST1, Po2 CORE↔DIST2, Po1 HN-SW01↔HN-SW02 (channel-group X mode active).
  5. Rapid-PVST+: spanning-tree mode rapid-pvst mọi switch. HQ: CORE spanning-tree vlan 1-4094 root primary, DIST1 root secondary. HN: SW01 root primary. ĐN: SW01 root primary. Cổng nối PC: spanning-tree portfast + bpduguard enable.
  6. SVI + HSRP (HQ): trên DIST1/DIST2 bật ip routing, SVI VLAN 10/20/30/40/99 theo bảng 1.4. HSRP version 2, group = VLAN ID, VIP = .1, DIST1 priority 110 + preempt, DIST2 priority 100 + preempt. SVI 100 không chạy HSRP (chỉ OSPF).
  7. DHCP tập trung tại HQ trên HCMC-EDGE-RTR01 (server = Loopback0 10.10.254.1): 1 pool cho mỗi VLAN user của cả 3 site (10/20/30/40 × 3 = 12 pool), ip dhcp excluded-address .1–.10 mỗi subnet, default-router, dns-server 10.10.254.1, domain-name tvi.lab.
  8. DNS: trên EDGE ip dns server + vài bản ghi ip host (ví dụ edge.tvi.lab, internet.tvi.lab 8.8.8.8) để demo phân giải tên.
  9. DHCP relay: SVI DIST1/DIST2 tại HQ và subinterface router HN/ĐN đặt ip helper-address 10.10.254.1 (subinterface router chi nhánh do P2 tạo, P1 chỉ thêm helper).

Bàn giao: TVI_Lab.unl, sơ đồ Draw.io + PNG, khối [P1] trong file .cfg của 6 switch + DHCP/DNS trên EDGE.

Bằng chứng: show vlan brief, show interfaces trunk, show etherchannel summary, show spanning-tree vlan 10 (CORE “This bridge is the root”), show standby brief, show ip dhcp binding, VPCS ip dhcp nhận IP đúng ở cả 3 site.

PHẦN 2 – IP SCHEMA, OSPF, eBGP (Bước 2, 5, phần BGP của bước 6)

  1. IP schema TVI_IP_Addressing_Schema.md: bảng 1.4 đầy đủ (network, mask, prefix, range, broadcast, gateway, số host khả dụng, IPv6 /64), bảng IP từng interface của từng thiết bị, giải thích cách chừa chỗ mở rộng 10k+ user và khối IoT /18. Nộp ngày 1 để mọi người dùng chung.
  2. Subinterface chi nhánh: HN/ĐN Gi0/1.10/.20/.30/.40/.99 (encapsulation dot1Q), IP gateway theo bảng.
  3. OSPFv2 process 1, router-id = Loopback0:
    • HQ Area 0: EDGE, DIST1, DIST2 trên VLAN 100 + Loopback; mạng user là passive-interface.
    • HN Area 1, ĐN Area 2: mạng LAN + Loopback của router chi nhánh. Tunnel10/20 thuộc Area 0 (P3 tạo tunnel, P2 thêm vào OSPF) → router chi nhánh là ABR.
    • Summarization trên ABR chi nhánh: area 1 range 10.20.0.0 255.255.0.0, area 2 range 10.30.0.0 255.255.0.0. Kiểm tra HQ thấy O IA 10.20.0.0/16.
    • EDGE: default-information originate để DIST nhận route mặc định.
  4. ISP-CLOUD-RTR01: AS 65100, Lo0 8.8.8.8/32 quảng bá vào BGP, neighbor x.x.x.2 default-originate cho cả 3 khách hàng.
  5. eBGP HQ 65001 / HN 65002 / ĐN 65003 với ISP: network đúng /30 WAN của mình. Mỗi site nhận default route từ ISP → chi nhánh đi Internet trực tiếp (không vòng về HQ, khớp yêu cầu “direct cloud access” của đề – nhớ ghi trong báo cáo). Không đưa 10.x vào BGP và không đưa IP public vào OSPF (tránh lỗi recursive routing tunnel).
  6. IPv6 (mức tối thiểu đủ điểm): ipv6 unicast-routing, gán IPv6 cho SVI/subinterface user, VLAN 100, Loopback; OSPFv3 Area 0 trong HQ (EDGE, DIST1, DIST2). VPCS lấy IPv6 bằng ip auto (SLAAC) và ping6 gateway. IPv6 liên site: không bắt buộc, ghi là bước tiếp theo.

Bàn giao: schema .md, khối [P2] trên 4 router + DIST1/DIST2 + ISP.

Bằng chứng: show ip ospf neighbor, show ip route ospf (có O IA summary), ping Loopback trong site, show ip bgp summary (3 neighbor Established trên ISP), show ip route bgp, show ipv6 ospf neighbor, show ipv6 interface brief.

PHẦN 3 – GRE over IPsec & QoS (Bước 6 phần tunnel, Bước 8)

  1. IPsec trên 3 router biên: crypto isakmp policy 10 (encr aes 256, hash sha256, authentication pre-share, group 14), crypto isakmp key TVI_Secret_Key2026! address <IP public đối diện>, crypto ipsec transform-set TVI-TS esp-aes 256 esp-sha256-hmac + mode transport, crypto ipsec profile TVI-PROF.
  2. Tunnel10 HQ↔HN, Tunnel20 HQ↔ĐN: tunnel source Gi0/0, tunnel destination <IP public>, tunnel protection ipsec profile TVI-PROF, ip mtu 1400, ip tcp adjust-mss 1360, ip ospf network point-to-point. Báo P2 đưa tunnel vào OSPF Area 0.
  3. Kiểm tra: PC Hà Nội/Đà Nẵng ping và traceroute tới PC HQ (10.x ↔ 10.x) đi qua 10.255.255.x; ISP không có route 10.x (chứng minh bằng show ip route trên ISP).
  4. QoS DiffServ (MQC) trên 3 router biên:
    • Phân loại + đánh dấu (input trên cổng LAN: EDGE Gi0/1, chi nhánh các subinterface): ACL VOICE = UDP 16384–32767 → set dscp ef; ACL VIDEO = UDP 5004–5005 → set dscp af31.
    • Hàng đợi (output trên Gi0/0 WAN): class EF → priority percent 20; class AF31 → bandwidth percent 30; class-default → fair-queue. (GRE tự copy DSCP ra header ngoài nên match DSCP trên cổng vật lý vẫn đúng; có thể thêm qos pre-classify trên tunnel.)
    • Test: từ VPCS ping <IP PC HQ> -2 -p 16500 -c 50 (UDP voice) và -p 5004 (video) → counter tăng ở show policy-map interface.

Bàn giao: khối [P3] trên 3 router biên.

Bằng chứng: show crypto isakmp sa (QM_IDLE), show crypto ipsec sa (encaps/decaps tăng), show interface tunnel10 up/up, ping + traceroute xuyên tunnel, show policy-map interface Gi0/0 và show policy-map interface Gi0/1.

PHẦN 4 – NAT, ACL, L2 SECURITY, AUTOMATION + TỔNG HỢP BÁO CÁO (Bước 7, 9, 10)

  1. PAT trên 3 router biên: ip nat inside (cổng/subinterface LAN), ip nat outside (Gi0/0). ACL NAT_INSIDE: deny ip 10.0.0.0 0.255.255.255 10.0.0.0 0.255.255.255 rồi permit ip 10.0.0.0 0.255.255.255 any; ip nat inside source list NAT_INSIDE interface Gi0/0 overload. Test: VPCS ping 8.8.8.8, show ip nat translations.
  2. ACL cô lập Guest (ip access-list extended GUEST_IN, áp in trên SVI 40 của DIST1 + DIST2 và subinterface .40 ở HN/ĐN): 
    permit udp any any eq bootps          ! DHCP
permit udp any host 10.10.254.1 eq domain   ! DNS HQ
deny   ip any 10.0.0.0 0.255.255.255  ! cấm toàn bộ Corp
deny   ip any 192.168.0.0 0.0.255.255 ! cấm Management
